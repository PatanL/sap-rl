# Outcome boundary for v31c

The worktree changed while training was running. The Rust owner added a single-fight C interface. The audit saved the shared object, its two rule tables, the interface source, and their digests in [rust-snapshot](rust-snapshot/SHA256SUMS). No file under engine-rs or either engine checkout was changed.

One process initializes the data directory once, resolves pet/status names to table IDs once, and reuses two fixed buffers (five slots × seven signed 32-bit fields). For a battle the caller supplies two front-first living-pet lists, their lengths, and the exact unsigned 32-bit battle seed from the paired world. Fields are species, effective attack, effective HP (both folded and clipped exactly as the v31 Battle copy would do), total XP, perk, consumed per-turn ability uses, and the Parrot’s actual copied species or explicit “no copy”. No inference-time access to private shop information is added. The ordinary environment requires the 0/1/2 outcome only. It still owns the public history, settlement, next turn, reward, and both pristine shop teams. The interface must not mutate either input. Negative error codes are errors, not draws. [Adapter](rust_boundary.py)

The existing C struct cannot encode a partially spent Wolverine friend-hurt counter, pending hurt state, arbitrary copied abilities, or swallowed-pet payloads. The adapter checks for unsupported state and uses the exact Python reference there. A production batch ABI could take contiguous [fights, 2, 5, fields] arrays, lengths and u32 seeds, and fill one outcome/error per input. Include explicit physical-slot indices for future shapes that require them, separate the effective ability from the source species, and pin a schema plus rule-table digest. The current single-call interface compacts living pets in seat order. The compared collector tape includes ordinary sparse boards, real END effects and seeds, with full state checked after the battle. Passing a replay fixture directly is weaker evidence than verifying that the actual Python END object was converted correctly.

For a future shop port, each actor needs a batch of persistent game handles. Reset accepts the paired-world seed per game. Step accepts the active-seat flags, native (type, source, target) triples and ten-bit END/freeze mask per active seat. Validate both seats before mutation. Expand the same physical-slot freeze toggles and retain their primitive action count. Preserve shop/ability random streams and battle seed consumption. Return public observations in the exact typed NumPy layout (including legality masks, public opponent history, normalizations and slot order), both rewards, battle-resolved flag, battle outcome, terminal flag, lives/wins, and active-seat masks. A completed turn must yield the real bootstrap observation before resetting a terminal game. A bulk operation producing these arrays directly into worker-owned pages also removes the Python encoder boundary. A shop engine that returns objects for the existing Python encoder leaves that measured work in place.

The paired ablation separates real Rust execution from ideal substitution. “Cached battle” returns the recorded winner after checking the battle seed, with the normal native shop and encoder still running. “Cached battle/no observations” also suppresses both public encodes, retaining native action and freeze-plan legality. “Replay” reads the recorded step metadata without simulating shop, battle or encoding. All modes check the same rewards, terminal flags and outcomes. Only the Rust result measures an actual port; an output replay exposes available work and cannot give a native shop speedup before a shop exists. [Fixed action tape benchmark](boundary_bench.py)
