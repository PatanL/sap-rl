# Rust vector collector on Turtle v31g

**The Rust and Python collectors produced byte-identical learner input** on 87,663 sampled seat actions, including 21,060 frozen-seat decisions, 3,322 combats and 256 completed matches. Of 66,603 live actions, 65,969 reached complete live turns and 65,602 were selected for the learner in 8 identical FIFO batches. Both sides discarded 0 stale decisions, retained 367 queued and ended with 634 in unfinished turns. [Parity receipt](results/parity-production.json)

The main check consumes the production target of 8,192 decisions and deterministically publishes three waves after selection. Separately, a deliberately over-fast publication clock advanced every 13 waves against a 1,024-decision target. That stress test generated 89,278 seat actions, compared 66,737 completed live decisions, accepted 1,028 and rejected 64,901 as stale, identically on both engines. Both tests use the same world-seed start; their decision counts must not be described as independent unique matches. [Lag stress receipt](results/parity-256.json)

The comparison runs the recorded 14.35M 26,022 policy on CPU in FP32, sampling separately against each backend with the same PyTorch RNG state per wave. Both collectors independently maintain their GRU bank, Python slot IDs, parent and periodic snapshot assignments, turn buffers and lag-one FIFO. The live policy is held fixed; the deterministic publication schedule exercises version stamps, lag and snapshot retirement. This tests transport equivalence. In actual asynchronous training, publication races and BF16 batch shape can change which legal samples are selected.

At every step the check compares shape, dtype and bytes of all 15 public arrays on both seats, active flags, lives/wins, battle-resolved/result, rewards, terminal/winner, sampled triples, joint freeze masks, log probabilities, memory and episode policy IDs. It separately compares every completed and selected segment’s owned observations and bootstrap observations, action, freeze mask, behavior log probability/version, reward, discount, initial GRU, terminal flag, seat-relative battle label, slot ID, order and length. Rust int8 0/1 flags are viewed as bool and its double rewards are converted to the historical float32 trajectory type. Stale actor scratch on an inactive seat is converted to the native sentinel (−1,10,5) and freeze mask zero. All public observations alias the native outputs, and complete trajectories own their storage before reset. Invalid native status raises. ## Interface and board recording

Ordinary training requires no additional engine field. Exact board scoring requires both post-END, pre-combat teams, including trigger counts and the Parrot’s effective copy, even on terminal fights. The public history omits these two fields. The actual 25,772 board archive has 1 fight with spent uses and 2 fights with copied abilities in 11,874 battles; filling defaults would already change real records. Per-game turn can be tracked from reset and battle events. An actual battle seed is useful to audit and to design counterfactual sampling; the ordinary trainer and external ghost sampler do not require it. ## Resource gate

No native GPU throughput, proof score or new board-recording time is reported before the explicit release. The benchmark checks that marker on every invocation. The historical 2,693 learned/s and 21,938 acting/s are comparison values from the earlier report, not native measurements in this study.

## Training signal

First test a battle-outcome-averaged **match-return** target, using 16 battle outcomes and at most three distinct public-value branches. Preserve the factual simulation, terminal objective, importance weights and opponents. The older M2 life-swing-only experiment lowered immediate noise but scored 49.5% directly against M1. The new proposal addresses the continuation and terminal terms that M2 left sampled. A matched M1/treatment test on two training seeds with large fixed-batch scoring and ranked-board checks fits a preallocated hour. Ranked opponents remain a separate, unapproved option.
